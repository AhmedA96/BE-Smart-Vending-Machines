ISSUES FIXED IN DETAIL
======================

1. DOCKER PERMISSION DENIED
   ─────────────────────────
   Error: permission denied while trying to connect to docker API
   Root Cause: ubuntu user not in docker group on new ASG instances
   
   Solution Applied:
   $ sudo usermod -aG docker ubuntu
   
   Permanent Fix Needed:
   Add to EC2 launch template user data

   Documented in: DEPLOYMENT_TROUBLESHOOTING.md - Issue 1

2. SOLID QUEUE CONFIGURATION ERROR
   ────────────────────────────────
   Error: Container restarting, "Solid Queue has gone away"
   Root Cause: puma.rb checked `if ENV['SOLID_QUEUE_IN_PUMA']`
               In Ruby, string "false" is truthy (not nil/false)
               Web servers had SOLID_QUEUE_IN_PUMA="false" but
               Puma still loaded the plugin, causing initialization error
   
   Solution Applied:
   Changed: if ENV['SOLID_QUEUE_IN_PUMA']
   To:      if ENV['SOLID_QUEUE_IN_PUMA'] == 'true'
   
   Added comments explaining Ruby truthiness behavior
   
   File: config/puma.rb
   Documented in: DEPLOYMENT_TROUBLESHOOTING.md - Issue 2

3. DATABASE MISSING ON SCALE-UP
   ────────────────────────────
   Error: 500 on /users/sign_in
          ActiveRecord::NoDatabaseError (vndgme_production not found)
   Root Cause: When ASG scales up, new instances need database init
   
   Solution Applied:
   $ kamal app exec -d production "bin/rails db:create"
   $ kamal app exec -d production "bin/rails db:migrate SKIP_POSTGIS_EXTENSION=true"
   
   Why SKIP_POSTGIS_EXTENSION?
   - postgis extension already exists on RDS
   - Trying to create again causes: duplicate key violation
   - Skip flag prevents re-creation
   
   Permanent Fix Needed:
   Add to post-deployment hook or automation
   
   Documented in: DEPLOYMENT_TROUBLESHOOTING.md - Issue 4

4. BASTION SSH ACCESS
   ───────────────────
   Error: Could not connect via bastion to app servers
   Root Cause: User's IP not in bastion security group
   
   Solution Applied:
   Added IP 102.44.221.234/32 to bastion security group
   
   Permanent Process:
   - Check your IP: curl https://checkip.amazonaws.com
   - Add to SG: aws ec2 authorize-security-group-ingress ...
   
   Documented in: DEPLOYMENT_TROUBLESHOOTING.md - SSH issues

KEY LEARNINGS
=============

1. Ruby Truthiness
   - String "false" is truthy (not nil/false)
   - Always use explicit comparison: == 'true'
   - Add comments explaining this

2. ASG Scale-Up Requires Setup
   - New instances need docker group setup
   - New instances need database initialization
   - Add both to launch template or automation

3. Documentation Is Critical
   - Clear troubleshooting guides reduce downtime
   - Comments in code help future maintainers
   - Index helps developers find info quickly

4. Testing Checklist Prevents Issues
   - Verify API endpoints after deploy
